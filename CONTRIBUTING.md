# Contribución

1. Partir de la versión actual de `develop`.
2. Implementar un cambio de alcance concreto. Para trabajo en equipo, crear una rama `feature/descripcion` y proponerla a `develop`.
3. Ejecutar `npm run validate` y comprobar visualmente móvil y escritorio.
4. Describir el resultado, su propósito y la validación en el pull request.
5. Para publicar, abrir un pull request de `develop` a `main` y esperar el check **Validate**.
6. Integrar el pull request y comprobar el flujo de entrega. Sin la integración activada, el sitio no se despliega.
7. Sincronizar después `develop` con `main`, conservando el historial de integración.

No incluir secretos, capturas de paneles privados, datos de clientes ni información interna de infraestructura. Los cambios de contactos y macros requieren confirmación comercial. Las imágenes nuevas deben tener permiso de uso y optimización apropiada.
